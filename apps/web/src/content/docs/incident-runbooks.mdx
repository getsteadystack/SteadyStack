When an outage strikes at 3:00 AM, every minute spent searching for documentation increases downtime. SteadyStack **Incident Runbooks** attach remediation playbooks, debug endpoints, and context directly into incident payloads, Slack alerts, and PagerDuty notifications.

---

## What to Include in a Runbook

A production-ready runbook should contain:

1. **Service Architecture Diagram**: Summary of dependencies (e.g. Origin Server $\rightarrow$ Redis Cache $\rightarrow$ PostgreSQL DB).
2. **First-Response Checklist**:
   - Verify cloud provider status (AWS, Cloudflare, Vercel).
   - Check origin error logs (`tail -f /var/log/nginx/error.log` or Datadog log queries).
   - Test internal origin health endpoint directly via curl.
3. **Escalation Contacts**: Primary and secondary domain experts and third-party vendor contact numbers.
4. **Rollback & Failover Procedures**: Step-by-step CLI commands to trigger DNS failover or redeploy previous release tags.

---

## 1. Linking Runbooks to Monitors

1. Navigate to **Dashboard → Monitors → Edit Monitor**.
2. Under **Incident Management**, paste your Markdown Runbook or external documentation URL (e.g. `https://wiki.youragency.com/runbooks/payment-api`).
3. Whenever an incident opens, the runbook link and summary instructions are immediately injected into all outgoing alert notifications.

---

## 2. Example Markdown Runbook Template

```markdown
### 🚨 Triaging Payment Gateway Outages

1. **Test Origin Health Directly**:
   `curl -svo /dev/null -H "Host: api.acme.com" http://10.0.1.50/health`
2. **Check Database Connection Pool**:
   Ensure active connection count is below max limit in PgBouncer.
3. **Trigger Read-Only Mode**:
   If DB is unresponsive, set `MAINTENANCE_READ_ONLY=true` in Cloudflare Worker KV.
```
